# Фазы разработки

Порядок не случайный: каждая фаза — работающий продукт. Остановка после любой оставляет
пользователю полезный сайт.

Легенда статуса: ✅ готово · 🟡 в работе · ⬜ запланировано.

---

## Фаза 1. Расписание 🟡

**Объём.** Календарь сезона, страницы этапов, время в часовом поясе пользователя, обратный
отсчёт до ближайшей сессии, базовые уведомления в браузере (тост о старте).

**Что реализовано в MVP сейчас.**
- `apps/api`: `DataProvider` + `JolpicaProvider` за token-bucket; кэш сезона в Postgres с TTL;
  эндпоинты `/api/health`, `/api/v1/seasons`, `/api/v1/schedule`, `/api/v1/meetings/{round}`,
  `/api/v1/next-session`. Сериализаторы не отдают сырые объекты провайдера.
- `apps/web`: главная с ближайшей сессией и обратным отсчётом, `/schedule`, страница этапа
  `/schedule/[round]`, время в локальном часовом поясе, `<DataAttribution/>`.
- `docker-compose`: postgres + redis + api + web.

**Осталось по фазе.** Тост-напоминание о старте по явному включению; выбор часового пояса в
шапке; ISR-ревалидация; OG-картинки этапов.

**Готово, когда:** гость без регистрации видит, когда следующая сессия по его времени, и может
включить напоминание.

## Фаза 2. Результаты 🟡

**Объём.** Итоги сессий, таблицы пилотов и конструкторов, страницы гонщиков и трасс, круги,
пит-стопы, стинты. Alembic-миграции (вводятся здесь). Автоген TS-типов из OpenAPI (ADR-006).

**Сделано.** Реальные данные из Jolpica (TTL-кэш в процессе; RU-имена пилотов, маппинг команд,
локализация трасс в `localization.py`):
- личный зачёт и кубок конструкторов (`/api/v1/standings/*`), страница `/standings`;
- итоги гонок и квалификация (`/api/v1/results|qualifying/{round}`) на странице этапа;
- прошедший этап с подиумом на главной;
- страницы пилотов `/drivers/{id}` (профиль, статистика, результаты сезона), имена кликабельны;
- контуры трасс (`public/tracks/*.svg` из открытого датасета) на карточках и странице этапа.

**Осталось:** страницы трасс, Alembic-миграции, автоген TS-типов из OpenAPI.
Кэши зачёта/итогов/профилей вынесены в общий Redis (`app/cache.py`) с graceful-fallback.

**Готово, когда:** страница вида «результаты квалификации гран-при» индексируется и
открывается быстрее 2 секунд.

## Фаза 3. Живой тайминг ⬜

**Объём.** `apps/ingest` (scheduler/live/post-session), Centrifugo, `apps/events`, таблица
позиций, интервалы, шины, флаги, сообщения рейс-контроля на русском. Полный центр уведомлений
и Web Push (VAPID). Подключение `OpenF1Provider`. Авторизация (magic link + Yandex ID, JWT).

**Ключевые свойства.** Идемпотентность ingest; буфер реплея (снапшот из Redis при подключении);
деградация при обрыве источника («данные задерживаются» + таймер, не пустой/замороженный экран).

**Готово, когда:** сессия отработана вживую от начала до конца без ручного вмешательства,
обрыв источника отработан корректно.

---

## Фаза 4. Телеметрия ⬜

**Объём.** Графики скорости/газа/тормоза/DRS/передач на uPlot; сравнение двух пилотов на одном
круге; карта трассы с позициями. Телеметрия — отдельными каналами Centrifugo по подписке.

**Готово, когда:** два круга разных пилотов сравниваются за 3 клика, график не проседает по кадрам.

---

## Фаза 5. Комьюнити ⬜

**Объём.** Чат (мини-чат на странице), профили, уровни/XP, топы (просмотренные сессии, точность
прогнозов, стаж), модерация из интерфейса (`apps/admin`). Правила чата живым языком.

**Готово, когда:** модератор мьютит и удаляет сообщение из интерфейса, а не из базы.

---

## Фаза 6. Стримы ⬜

**Объём.** Только после подписанных оферт минимум с двумя кастерами. Страницы кастеров, embed
(Twitch/VK Video/YouTube), регулятор смещения звука (сохраняется локально по платформам),
мгновенное отключение (`is_active`, эффект <5 c). Видео — по [video-strategy.md](video-strategy.md).

**Готово, когда:** стрим кастера отключается из админки за <5 секунд; регулятор смещения
работает и запоминает значение.
